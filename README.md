# EcoPet Planner — отчёт о выполненных работах

EcoPet Planner — веб-приложение для создания мемориала питомца в виде дерева, выбора места посадки и ведения дневника ухода. Ниже приведён отчёт о выполненных работах backend- и frontend-разработки, API, локальном запуске, проверках и ограничениях реализации.

Для подробного описания архитектуры, решений, реализации, проверок и подготовки к защите см. [REPORT_FOR_DEFENSE.md](REPORT_FOR_DEFENSE.md).

## Обзор системы

- **Frontend:** React, Vite, Leaflet, React-Leaflet.
- **Backend:** Django REST Framework, SimpleJWT, ReportLab, Pillow.
- **База данных:** PostgreSQL. SQLite не используется.
- **Картографические данные:** тайлы OpenStreetMap, загружаемые браузером из интернета.
- **Архитектура:** одностраничное React-приложение обращается к REST API Django.

## Backend-разработка

### Пользователи и авторизация

- Добавлена пользовательская модель с уникальным email и необязательным телефоном.
- Реализованы регистрация, вход и обновление JWT-токена.
- Добавлен защищённый API профиля: пользователь может просматривать и изменять только свои данные.
- Защищённые API используют JWT-аутентификацию.

### Карточки питомцев

- Реализованы создание, список, просмотр, изменение и удаление карточек питомцев.
- Список и операции с карточкой ограничены владельцем.
- Карточка хранит имя, вид, породу, вес, даты рождения и ухода, фотографию.
- Принимаются фотографии через `multipart/form-data`, максимальный размер — 10 МБ.
- Ручной ввод возраста убран из frontend. Возраст в полных годах вычисляется по датам рождения и ухода и показывается как производное значение; старое поле `age_years` оставлено в БД для совместимости.
- Добавлена обработка пустых необязательных дат.

### Расчёт и сохранение мемориала

- API расчёта сохраняет сценарий, регион, климат, почву, освещённость, близость воды, предпочтения ухода и темпа роста, комментарий.
- Авторизованный пользователь может связать расчёт со своей карточкой питомца.
- Срок биодеградации рассчитывается как `Ttotal = Tbase × Kweight × Ksoil × Kclimate`. Для текущей смеси мицелия и прессованного торфа `Tbase = 6` месяцев; весовые коэффициенты: `<5 кг — 0.9`, `5–20 кг — 1.0`, `>20 кг — 1.2`; почвенные: чернозём `0.9`, песок и суглинок `1.0`, глина `1.3`; климатические: южный `0.9`, умеренный `1.0`, континентальный `1.1`, северный `1.3`.
- Расчёт возвращает вес-снимок, числовой прогноз в месяцах, компоненты формулы, рекомендуемый размер капсулы и подходящее дерево при наличии совпадения по климату.
- Каталог деревьев начально заполняется миграцией данными десяти пород. Подбор сначала ограничивает кандидатов совместимым климатом, затем ранжирует по почве, предпочтительному уходу и темпу роста.

### Посадки, зоны и дневник

- Реализована выдача активных эко-зон и управление ими через staff API.
- У зоны хранятся координаты, адрес, регион, климат, близость к воде, правила и признак наличия ухода.
- Каталог включает семь демонстрационных точек в Москве, Московской области, Санкт-Петербурге, Краснодарском крае, Новосибирской области и Карелии, охватывающих четыре климатические зоны.
- Климат выбирается автоматически по региону; при ответе «Да» на вопрос о водоёме карта оставляет только зоны с признаком близости к воде.
- Демонстрационные координаты и точки у воды явно помечены как примеры; они не подтверждают фактическое разрешение на посадку.
- Реализованы создание и список посадок, добавление записей ухода.
- Проверяется владение расчётом, питомцем, посадкой и дневниковой записью.
- Посадка на собственном участке может быть сохранена без эко-зоны: `eco_zone` допускает `null`, описание места хранится в `location_details`.

### PDF-паспорт

- PDF формируется из сохранённых сведений расчёта и питомца.
- Включает анкету, фото при наличии, указанные параметры и рекомендации.
- Добавлен в проект шрифт Noto Sans с поддержкой кириллицы и его лицензия SIL Open Font License.
- Оформление PDF включает цветную шапку, заголовки разделов, таблицы и номера страниц.
- При неизвестном ID расчёта endpoint возвращает `404 Not Found`.

## Frontend-разработка

### Навигация и профиль

- Дневник ухода находится на главной странице «Мой сад».
- Личный кабинет доступен как отдельный экран из шапки и мобильного меню.
- В кабинете можно менять данные пользователя, редактировать карточки питомцев и загружать/заменять фото.
- Ввод возраста удалён; даты рождения и ухода доступны.

### Создание мемориала

- Форма собирает данные питомца, даты, фотографию, условия места и пожелания к мемориалу.
- Проверяются обязательные поля и регион до отправки.
- После расчёта отображаются рекомендации и доступно скачивание PDF.
- Вариант «Заповедная зона» убран.
- Для «Собственного участка» создание посадки завершается без карты и эко-парка; запись сохраняется с пустой зоной, после чего открывается «Мой сад».
- Для остальных сценариев пользователь может перейти к выбору эко-парка.

### Карта и список зон

- Схематичная карта заменена интерактивной картой Leaflet с маркерами.
- Добавлен поиск по названию, адресу и типу зоны.
- Зону можно выбрать из списка или нажатием на маркер.
- Описание зоны вынесено в боковую панель, не перекрывающую карту.
- Высота карты ограничена областью окна под хедером; боковая панель прокручивается до описания и кнопки выбора.
- На узких экранах список и карта расположены вертикально, карта сохраняет ограниченную высоту.

### API-клиент

- Общий клиент отправляет JSON и `FormData` без ручной установки multipart boundary.
- Access-токен обновляется через refresh-токен.
- Ошибки запросов отображаются в интерфейсе.
- PDF обрабатывается как бинарный ответ и скачивается браузером.

## Пользовательские сценарии

1. Пользователь регистрируется и входит в приложение.
2. Заполняет данные питомца и условия посадки, получает рекомендацию и скачивает PDF.
3. Выбирает собственный участок и завершает создание без выбора эко-парка либо выбирает подходящую зону на карте.
4. На странице «Мой сад» просматривает посадку и ведёт дневник ухода.
5. В отдельном личном кабинете обновляет свои данные и карточки питомцев.

## API

Все маршруты имеют префикс `/api/v1/`. Для защищённых запросов передаётся `Authorization: Bearer {access_token}`.

| Метод | Endpoint | Доступ | Назначение |
|---|---|---|---|
| `POST` | `/auth/register/` | Публичный | Регистрация |
| `POST` | `/auth/login/` | Публичный | Получение JWT-токенов |
| `POST` | `/auth/refresh/` | Публичный | Обновление access-токена |
| `GET`, `PATCH` | `/auth/profile/` | Авторизованный | Просмотр и изменение своего профиля |
| `GET`, `POST` | `/calculator/pets/` | Авторизованный | Список своих питомцев и создание карточки |
| `GET`, `PUT`, `PATCH`, `DELETE` | `/calculator/pets/{id}/` | Владелец | Работа со своей карточкой |
| `GET` | `/calculator/tree-species/` | Публичный | Каталог пород деревьев |
| `POST` | `/calculator/calculate/` | Публичный; связь с питомцем — авторизованный | Расчёт мемориала |
| `GET` | `/calculator/{calculation_id}/pdf/` | Публичный | Скачать PDF-паспорт |
| `GET` | `/zones/` | Публичный | Активные эко-зоны |
| `GET`, `POST` | `/admin/zones/` | Staff | Список и создание зон |
| `GET`, `PUT`, `PATCH`, `DELETE` | `/admin/zones/{id}/` | Staff | Управление зоной |
| `GET` | `/dashboard/` | Авторизованный | Данные посадки |
| `GET`, `POST` | `/tracker/plantings/` | Авторизованный | Список и создание своих посадок |
| `POST` | `/tracker/logs/add/` | Авторизованный | Добавление записи ухода |

Подробные примеры полей и ответов приведены в [backend/API.md](../backend/API.md).

## Структура данных

- `User` — email, имя пользователя, телефон.
- `Pet` — сведения о питомце и фотография.
- `TreeSpecies` — каталог пород и характеристик деревьев.
- `CapsuleCalculation` — входные параметры и рекомендации.
- `EcoZone` — зона посадки и её координаты.
- `PlantedTree` — посадка, связанная с питомцем и расчётом; зона необязательна.
- `TreeCareLog` — дата, описание и фото записи ухода.

На одну запись расчёта может приходиться не более одной посадки.

## Локальный запуск

### Требования

- Python и PostgreSQL.
- Node.js и pnpm.
- Интернет для загрузки тайлов карты.

### Backend

Из каталога репозитория:

```powershell
Set-Location .\backend
py -m venv .\venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Создайте `backend/.env` и укажите параметры локальной PostgreSQL-базы:

```dotenv
POSTGRES_DB=pet_memorial
POSTGRES_USER=postgres
POSTGRES_PASSWORD=<ваш-пароль>
POSTGRES_HOST=127.0.0.1
POSTGRES_PORT=5432
```

Создайте базу PostgreSQL и запустите backend:

```powershell
python manage.py migrate
python manage.py runserver
```

По умолчанию backend доступен по адресу `http://127.0.0.1:8000`.

### Frontend

В отдельном терминале:

```powershell
Set-Location .\frontend
corepack pnpm install
corepack pnpm dev
```

Frontend по умолчанию запускается на `http://localhost:8443`. Vite проксирует `/api` на `http://127.0.0.1:8000`. Production-сборка:

```powershell
corepack pnpm build
```

## Проверки

- Production-сборка frontend проходила после изменений интерфейса и PDF.
- Набор `calculator`: **7 тестов**, включая генерацию PDF и Unicode-шрифт.
- Набор `users`: **4 теста**, включая редактирование профиля.
- Набор `zones`: **3 теста**, включая публичный список и права staff.
- В успешном запуске тестов Django system check не обнаружил проблем.
- Объединённый backend-запуск ранее прерывался из-за обрыва PostgreSQL-соединения; наборы запускались отдельно с `--keepdb`.

## Текущие ограничения

- Расчёт упрощён: размер капсулы выбирается по весу, срок разложения рассчитывается по заданным экспертным коэффициентам, а породы ранжируются по климату, почве и предпочтениям. Полноценная агрономическая экспертная модель не реализована.
- Для отображения зоны нужны активная запись и корректные координаты.
- Тайлы OpenStreetMap требуют интернет-соединения.
- Возраст питомца вычисляется в полных годах по датам рождения и ухода, когда обе даты указаны. Старое поле возраста в БД сохранено для совместимости; введённое вручную значение не используется как источник.
- Фотографии хранятся в media-каталоге backend. Для production необходимо настроить постоянное хранилище и раздачу media-файлов.
